# unotest-fixtures-api

Бэкенд-фикстура для dogfood-набора: против неё гоняются DSL-функции
`apiCall()` и `upload()`. Playground браузерный и из Node недостижим,
поэтому у sandbox-примитивов свой ответчик.

Живёт на **https://fixtures.unotest.com** (деплой по образцу playground).
Тот же файл поднимается локально — никакой отдельной сборки нет.

## Запуск

```sh
node unotest/fixtures/api/server.mjs        # 127.0.0.1:8787
PORT=9000 HOST=0.0.0.0 node server.mjs      # на сервере
```

Зависимостей нет (`node:http` + `node:crypto`), Node 20+.

## Ручки

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/health` | ok + аптайм + число записей |
| POST | `/items` | создать `{marker, name?, qty?}` → 201 с `id` |
| GET | `/items?marker=X` | только записи этого маркера |
| GET/PATCH/DELETE | `/items/<id>` | чтение / правка `{name?, qty?}` / удаление |
| POST | `/echo` | вернуть метод, query, заголовки и тело |
| GET | `/status/<code>` | ответить этим статусом (проверка кодов) |
| POST | `/upload` | разобрать multipart → поля, имена файлов, размеры, sha256 |

## Правила

- **Маркер обязателен.** `POST /items` без `marker` — 400. Каждый
  сценарий тегирует записи `randomWord()`-маркером и читает только
  свои: два параллельных прогона не должны видеть друг друга.
- **Состояние временное.** Всё в памяти, TTL записи — час (`ITEM_TTL_MS`),
  потолок `MAX_ITEMS`, тело — 2 МБ (`MAX_BODY_BYTES`). Рестарт = легальный
  сброс, инстанс публичный и накапливать не должен.
- **Данных пользователей тут нет** и быть не может: это стенд для тестов.
